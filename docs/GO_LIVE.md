# 本番開始チェックリスト

dev（検証用）で動いているものを、本番へ入れるときの確認表です。上から順に進め、各項目の `[ ]` を `[x]` にしていきます。

> **これは「システム全体の初回リリース」です。** `prod` ブランチは `dev` より大きく遅れており、Discord VC・クイズ・ナイスチャレンジなど、これまでの機能がすべて本番への初めての反映になります。入口を閉じたまま立ち上げ、確認が済んでから開けます。

構築の手順そのものは [SETUP.md](SETUP.md) です。ここには、**確認すること・順番・止め方**だけを書きます。

## A. dev での確認（本番に入れる前）

デプロイ済みのコードで、**dev の Slack ワークスペース**で確かめます。自動テストでは確かめられないものです。

### A-1. 反映
- [ ] dev の GAS エディタで **`setupTriggers()` を1回実行**し、実行ログにエラー・警告が無い
- [ ] 「クイズ設定」に **出題の切り替え・出題を始める日・次の出題** の3行が、「投稿先チャンネル」の下に入っている
- [ ] 各ログシートの見出しが新しい名前になっている（投稿ID・返信ID・出題メッセージID・告知メッセージID・転送元メッセージID・転送先メッセージID・Ord番号・Q番号）
- [ ] 「ナイスチャレンジレビューログ」の末尾に **投稿者・投稿内容・返信内容** の列がある
- [ ] ナイスチャレンジ用フォームに、必須の設問「活動の概要をひとことで！（※必須）」が「成果物のリンク」の前にある（既存のフォームは手で足す。タイトルは完全一致）
- [ ] 「ナイスチャレンジ投稿ログ」の末尾に **本文の返信ID** の列がある（既存の行は空のままでよい）
- [ ] イベント登録フォームの「主催者のSlackユーザーID」に案内文が出る（弟子用・師匠用の両方）

### A-2. イベント管理（最重要）
- [ ] `/event` → フォーム送信 → **告知が出る**（カレンダー予定・シートへの記録・編集用URLのDMも）
- [ ] 2アカウントで「参加する」→ 一方を満員にしてキャンセル待ち → 取り消しで**繰り上げ**のDM
- [ ] 運営が「参加する」を押す → 「運営として登録済みです」と出る
- [ ] **中止する → 告知スレッドに参加者・キャンセル待ちのメンションが付き、通知が届く**
- [ ] すでに中止のイベントを再送信しても、中止のお知らせが繰り返されない
- [ ] 存在しない主催者ID（実在するIDの末尾を1文字変える）で送信 → **登録されず**、告知チャンネルに案内が出る
- [ ] 開始から12時間を超える設定（14:00開始・13:00終了）→ 差し戻される
- [ ] **中止したイベントを開催に戻す**（日時・開催形式は変えない）→ カレンダー予定が作り直され、告知の【中止】が消えてボタンが戻り、主催者へ「中止から開催に戻しました」のDMが届く
- [ ] 上を、開催形式を変えて（Meet・その他のオンライン・対面）も確かめる。参加登録が残っている
- [ ] 終了した日時のまま、開催に戻す → 差し戻される
- [ ] 登録済みのイベントで、**開催形式（対面 → Meet など）や場所を変える** → 告知スレッドに「変更前 → 変更後」と、参加者へのメンションが付き、**メンションの通知が届く**（DMは送られない）
- [ ] 開催に戻したとき、告知スレッドに「中止から開催に戻りました」と、参加者へのメンションが付き、通知が届く
- [ ] （任意）`SLACK_CHANNEL_ID` を一時的に存在しないID（`C0000000000`）にして登録 → **予定が消え**、再送信の案内が届く。**確認後、必ず元の値に戻す**（公開チャンネルは、Bot が入っていなくても投稿できるため、Bot を外す方法では確かめられない）

### A-3. クイズ
- [ ] 「お休み」にして数秒待つ → 「次の出題」が `お休み中です` になる（編集トリガー）
- [ ] 「出題を始める日」に明日の日付 → 「次の出題」が明日になり、今日は出題されない
- [ ] 毎時の判定で、実際に1問だけ出題され、同じ日の次の判定では重ねて出ない
- [ ] 出題メッセージにスタンプ → 「クイズ回答ログ」に記録される

### A-4. ナイスチャレンジ
- [ ] `/review` → ID入力済みのフォームが開く → 送信 → **親の投稿（見出し・概要・対象・案内）が出て、スレッドの最初の返信に回答の内容と師匠のメンションが入る**（本人のメンションは親の投稿）
- [ ] 存在しない投稿者IDで送信 → **投稿されない**（回答はフォームに残る）
- [ ] 本人以外がスタンプ・返信 → レビューログに記録され、**投稿者・投稿内容・返信内容**が入る
- [ ] 返信を編集 → 返信内容が更新される。返信を削除 → 返信内容が消えて削除日時が入る
- [ ] 本文の返信にスタンプ → レビューログに記録され、「投稿ID」は親の投稿のもの
- [ ] 回答を編集 → スレッド内の本文と、親の投稿の概要・対象が更新される
- [ ] 変更前に出した投稿（本文が親にある形）の回答を編集 → 親の投稿が従来の形のまま更新される

### A-5. その他
- [ ] 絵文字転送: マッピングに行を足し、スタンプで転送される。マッピングが空なら何も起きない
- [ ] 参加ボタンを押したとき、「応答に失敗した」警告が出ないか（出る場合は頻度を控える。処理自体は完了する）
- [ ] 「ナイスチャレンジ投稿項目」シート（使われなくなった）を消した

## B. 本番の構築（入口を閉じたまま）

[SETUP.md](SETUP.md) の手順1〜7に沿って進めます。**本番のGASプロジェクトは、あなた個人のアカウントで作ります**（期の終わりに閉じる前提。引き継ぎは考えない）。

- [ ] 本番用の **GASプロジェクトを新規に作成**し、コードを入れる（手順1〜2）
- [ ] `Config.gs` の **`PROGRAM_NAME`** が、今の期の名前になっている
- [ ] **`bootstrap()` を実行**（手順3）。管理用・公開用のスプレッドシート、弟子用・師匠用フォーム、ナイスチャレンジ用フォーム、カレンダーが作られる
- [ ] 手動作業（手順4）
  - [ ] 運営用フォルダへ移動（運営のGoogleグループへ「編集者」で共有）
  - [ ] カレンダーを「一般公開」＋「予定の表示（すべての予定の詳細）」にする
  - [ ] 公開用スプレッドシートを「リンクを知っている全員」＋「閲覧者」にする。**管理用は共有しない**
- [ ] **本番用の Slack App** を作る（手順5）
  - [ ] マニフェストは、**最初は `slash_commands`（`/event`・`/review`）の定義を省いて**作る（`commands` スコープだけが残るときの扱いは、Slack の画面の案内に従う）
  - [ ] Bot User OAuth Token・Verification Token を控える
  - [ ] 告知チャンネルに Bot を招待する
- [ ] スクリプトプロパティを登録（手順6）: `SLACK_BOT_TOKEN`・`SLACK_VERIFICATION_TOKEN`・`SLACK_CHANNEL_ID`
  - [ ] **`SLACK_CHANNEL_ID` は、最初は「テスト用のチャンネル」にする**（公開の直前に、本番のチャンネルへ書き換える）
- [ ] **`setupTriggers()` を実行**（`bootstrap()` と同じ人が実行する）。実行ログにエラーが無い
- [ ] 管理用スプレッドシートに設定を入れる
  - [ ] 「師匠リスト」に師匠のSlackユーザーIDを登録
  - [ ] 「VCルームリスト」にDiscordの部屋を登録（**空だと、Discord VC を選んだ登録がすべて差し戻される**。TempVoice のハブチャンネルは載せない）
  - [ ] 「クイズ設定」は、**準備ができるまで「出題の切り替え」を「お休み」にしておく**
- [ ] Webアプリをデプロイし、`/exec` の URL を `WEBAPP_URL` に登録、Slack App の Request URL を差し替える（手順7）。`commands` スコープを含むときは、アプリを再インストールする
- [ ] **GitHub の production 環境**に変数を登録: `SCRIPT_ID`・`DEPLOYMENT_ID`（`CLASPRC_JSON` はリポジトリ共通。本番GASへ書き込める Google アカウントのものか確認）
- [ ] **初回の `dev → prod` PR をマージ**し、Deploy to GAS が成功する
- [ ] 本番で **`setupTriggers()` をもう一度実行**する（反映後のコードでシート・フォームを整えるため）

## F. 問題が出たときの止め方

初回リリースなので、「前のバージョンに戻す」ものがありません。次の順で止めます。

| 止めたいもの | 方法 | 戻し方 |
|---|---|---|
| イベントの登録全般 | フォームの「回答を受け付ける」をオフ。あるいは Slack App から `/event` を外す | オン／コマンドを戻す |
| クイズの出題 | 「出題の切り替え」を「お休み」にする | 「出題する」に戻す |
| ナイスチャレンジ | 「フォームのID」か「投稿先チャンネル」を空にする | 入れ直す |
| スタンプ転送 | マッピングの行の「有効」を「無効」にする（または行を空に） | 戻す |
| 告知が間違った場所に出る | `SLACK_CHANNEL_ID` を直す | — |
| すべて | GASのトリガーを外す（`setupTriggers()` で再登録できる）／Slack App を一時的に無効にする | `setupTriggers()` を実行 |

> 止めたあとは、告知済みのイベントの「参加する」ボタンは、Slack側に残ります。参加者へは、Slackで一言案内してください。
