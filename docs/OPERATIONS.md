# 使い方・運用フロー

運用・利用する人向けのドキュメントです。メンバーへの案内、日々の使い方、トラブルシューティングをまとめています。構築手順は [SETUP.md](SETUP.md)、Botの概要は [README](../README.md) を参照してください。

## メンバー（参加者・主催者）へ事前に案内すること

運用開始時に、ワークスペースのメンバーへ以下をアナウンスしておくとスムーズです。

| 案内すること | 理由 |
|---|---|
| **Slackプロフィールの「表示名（Display Name）」を設定する** | 参加ボタンを押すと表示名が出欠表（告知メッセージ・スプレッドシート）に載ります。**表示名が未設定の場合は代わりにプロフィールの氏名（Full Name）が載る**ため、本名を出したくない方は必ず設定してください |
| 告知チャンネルに参加する | 告知・予約はすべて告知チャンネル上で行われます |
| 通知（DM）を受け取れる状態にしておく | 参加確認・キャンセル待ちの繰り上げ・編集用URLの送付はBotからのDMで届きます。**BotのDMは通常のDM欄ではなく、サイドバーの「App」欄（アプリ名の会話）に届きます**。見当たらない場合はSlack内検索でアプリ名を探してください。アプリからのDMをミュートしていると気付けません |
| **イベント用カレンダーを自分のGoogleカレンダーに追加する** | コミュニティ全体でどんなイベントが動いているかを、自分の予定と重ねて一覧できます。**告知メッセージの「:calendar: カレンダーを開く」を押して、初回に出る「カレンダーを追加しますか？」でOKするだけ**です（2回目以降は自分のカレンダーが開きます）。日時変更・中止も自動で反映されます。※「他のカレンダーを追加 → URLで追加（iCal形式）」は取得間隔が数時間〜1日単位で直前の変更が届かないため使わないでください |

なお、表示名の変更はプロフィールから各自でいつでも行えます。表示名を変更しても、変更後に押したボタンから新しい表示名が使われます（反映は最大6時間キャッシュ分だけ遅れることがあります）。

## 運用フロー

### イベントの新規登録（主催者）

1. Slackの任意のチャンネルで **`/event`** と入力します → 本人にだけ見える返信で、**イベント登録フォームの「あなた専用リンク」**が届きます。
   - このリンクを開くと「主催者のSlackユーザーID」と「ステータス: 開催」が**入力済み**の状態でフォームが表示されます（IDの手入力が不要になり、入力ミスを防げます）。
   - 「師匠リスト」シート（後述）に登録された師匠が `/event` を打った場合は、**師匠用フォームのリンクだけが届きます**（弟子用フォームのリンクは表示されません）。登録されるイベントはすべて師匠イベント扱いになります。
   - ※フォームのURLを直接開いて手入力することも引き続き可能です。
2. 残りのイベント情報を入力・送信します。
3. 送信すると自動で以下が実行されます。
   - Googleカレンダーに予定を作成。開催形式が「Google Meet」なら **Meet URLが自動発行**され告知・シートに反映。「Discord VC」なら **VCルームリストから部屋を1室自動で確保**し、その部屋のURLが会場になります（後述）。「その他のオンライン / 対面」なら入力したURL・場所がカレンダーの場所欄に入ります。
   - Slackの告知チャンネルへ、**「✋ 参加する」「取り消す」ボタン付き**のイベント案内をBotが投稿。フッターには参加者リストと **「:calendar: カレンダーを開く」**（初回クリックで自分のGoogleカレンダーにイベント用カレンダーが追加され、以降は自分の予定と重なって表示されます）が付きます。
   - 管理用・公開用スプレッドシートへイベントを記録。
   - カレンダーの説明欄に概要・事前準備・参加者確認URL・Slackパーマリンクを書き込み。
   - 主催者のSlackへ **回答編集用URL** と **作成されたカレンダー予定へのリンク** がDMで届きます（編集用URLは変更・中止に必要なので保管してください）。予定リンクを開けば、意図した日時・場所で登録できているかをその場で確認できます。
     - ※このDMは通常のDM欄ではなく、**サイドバーの「App」欄（Botアプリ名の会話）** に届きます。届いていないように見える場合は、まずSlack内検索でアプリ名を探してください。

### 60分を超えるオンラインイベント（無料版Meetの制限対策）

- 開催形式「Google Meet」で60分を超えるイベントの場合、**カレンダー予定は60分ごとに自動分割**されます（例: 2時間 → 「イベント名（1/2）」「イベント名（2/2）」）。
- これは無料版Google Meetで3人以上の通話が60分で切断されるための措置です。**各回で別々のMeet URLを発行**するため、切断されたら**次の回のURLへ入り直すだけで待ち時間なし**に続行できます（同じURLへの即再入室で発生する数分間のクールタイムを避けられます）。各回の時間とURLの一覧は告知メッセージに掲載され、各カレンダー予定にもそれぞれのMeetリンクが紐づきます。
- **進行のコツ:** Meetの60分カウントは「通話の接続開始」からのため、カレンダーの区切りとは厳密には一致しません。**予定の区切りの数分前に主催者が休憩を宣言して全員いったん退出 → 次の回のURLへ入り直す**と、そこから新しい会議として60分がリセットされ、途中で突然切断されるのを防げます。

### Discord VCで開催する（会場の自動確保）

開催形式で「Discord VC」を選ぶと、**「VCルームリスト」シート（管理用①）**に登録された部屋から1室を自動で確保し、会場URLに設定します。会場URLの入力は不要です。

GASはDiscordのAPIを操作しません。確保といっても実際に入室を制限するわけではなく（VCは誰でもいつでも入れます）、**同じ時間帯に同じ部屋が二重に割り当てられないようにするための「札」**です。

#### VCルームリストの列

| 列 | 内容 |
|---|---|
| VC名 | 告知・カレンダー・主催者DMに出る表示名 |
| チャンネルURL | `https://discord.com/channels/{サーバーID}/{チャンネルID}` |
| 定員（目安） | この部屋を割り当ててよいイベント定員の上限。空欄は99として扱います |
| 所有者SlackユーザーID（任意） | 埋めると「その人の部屋」になります（下記） |
| 有効（未入力＝有効） | 「無効」にすると一時的に割り当て対象から外れます |
| メモ | 処理には使いません |

**行の並び順が優先順位です。** おまかせの自動割り当ては上から順に空きを探すため、**大きい部屋ほど下**に置いてください。そうすると小さいイベントに大部屋を取られず、大部屋は最後の砦として残ります。

> **一時VC（Join-to-Createで自動生成される部屋）と、その入口になるハブチャンネル（「➕ 部屋を作る」等）は絶対に登録しないでください。** ハブを会場として割り当てると、参加者が入った瞬間にそれぞれ別の一時VCへ飛ばされ、全員が散り散りになります。

シートを編集すると、フォームの「VC部屋」の選択肢がその場で貼り直されます（結果はシート上部のトーストで通知）。部屋を1行足せば、すぐフォームで選べるようになります。

#### 部屋の決まり方

主催者はフォームで開催形式に「Discord VC」を選ぶと「VC部屋」の設問へ進み、**「おまかせ」か、部屋の名指し**を選べます（他の形式ではこの設問は表示されません）。

- **おまかせ**（推奨）… ①主催者自身の部屋（所有者列が本人）が空いていればそれを最優先 → ②所有者が空欄の部屋を、定員で絞って行順に先頭から
- **名指し**… その部屋が空いていればそのまま確保します。埋まっていた場合、代わりの部屋を勝手に当てることはせず、**その時間に空いている部屋の一覧を添えて差し戻します**（指名した意味が消えないようにするためです）

**所有者列が守るのは「おまかせ」だけです。** 所有者を書いた個人VCは他の人のおまかせ先には選ばれませんが、**名指しすれば誰でも予約できます**（師匠の部屋を弟子が借りる運用を残すため、意図的にそうしています）。

したがって、**おまかせで割り振られる部屋を決めたいときは「所有者列を空けておくか、埋めるか」で調整します。** 誰でも使ってよい共有部屋は所有者を空欄にし、小さいものほどシートの上に置いてください。

なお定員（目安）は、人が溢れるのを防ぐ壁ではなく（Discordの通常VCは99人まで入れます）、**小さい会に大部屋を当てないための並べ替えのヒント**として使っています。

#### 差し戻しになる場合

フォーム記入中に空き状況を表示することはGoogleフォームの仕様上できないため、**埋まっている部屋を選んで送信 → 差し戻し**は避けられません。差し戻しの理由は主催者へDMで届きます。

- 名指しした部屋が、その時間に予約済み（空いている部屋の一覧を添えます）
- 名指しした部屋がリストに無い、または「無効」になっている
- イベント定員を収容できる部屋が**1室も登録されていない**（現在の最大人数を添えます）→ 定員を見直すか、シートの定員列の数字を実態に合わせてください
- 定員を収容できる部屋が**すべて予約済み**（おまかせで全滅した場合のみ）

#### 部屋が変わったときの周知

日時や開催形式を変更すると部屋を取り直すことがあります（イベント名の修正だけでは取り直しません）。**部屋が変わった場合は、開催日時の変更とまったく同じように、告知スレッドへの投稿と参加者・キャンセル待ちへのDMで変更前後の部屋名を通知します。** Slackはメッセージの編集では通知を出さないため、告知を書き換えるだけでは「いつもの部屋」に集まってしまう人が出るためです。

イベントを中止すると、その部屋は自動的に空きに戻ります。

### 入力ミス・二重登録の自動ガード

フォーム送信時にGASが内容を検証し、問題があると**登録・更新を行わずに主催者へDMで理由と修正用リンクを通知**します。「送信したのに告知が出ない」まま気付かない事態を防ぎます。

- 検証項目: 開始日時が過去でないか / **開始から終了までが12時間以内か**（終了時刻の打ち間違い対策。終了が開始以前だと翌日扱いになるため） / 定員が1以上の整数か / SlackユーザーIDの形式 / 開催形式が選択肢のいずれかか / 「その他のオンライン」「対面」での場所未入力 / Discord VCの部屋を確保できるか / 日時の形式
- **二重登録ガード:** 同じ主催者が同じ開始日時のイベントを既に持っている場合（＝「編集のつもりで新規送信」の典型パターン）は登録せず、既存イベントの編集用URLをDMで案内します。同名イベントでも開始日時が異なれば連続講座として通常どおり登録できます。
- 主催者のSlack IDが不正でDMを送れない場合のみ、告知チャンネルに「登録を受け付けられなかった」旨の案内が投稿されます。
- **主催者のSlack IDの形式は正しいが、Slackに存在しない場合**（打ち間違いなど）も、イベントは登録も告知もされず、同じ案内が告知チャンネルに投稿されます。確認するのは新規登録と、編集で主催者IDを変えたときだけです。Slackとの通信に失敗して確認できなかったときは、そのまま登録します。
- **Slackへの告知を投稿できなかった場合**（チャンネルIDの誤り、プライベートチャンネルにBotがいない、など。公開チャンネルには、Botが入っていなくても投稿できます）は、作ったカレンダー予定を削除し、シートにも書かずに、主催者へDMで再送信を案内します。同じ編集用URLから送り直せば、新規登録としてやり直せます。何度やっても同じなら、告知チャンネルの設定とBotの招待を確認してください。
- 主催者IDの設問には、`/event` で開くと入力済みになることとIDの調べ方を案内文として表示し、形式チェックも付いています（`setupTriggers()` で稼働中のフォームにも反映されます）。

### 参加登録・キャンセル（メンバー）

- 告知メッセージの **「✋ 参加する」ボタンを押す → 参加登録**（表示名が参加者リストに1行追記され、本人に確認通知が届きます）。
- **「取り消す」ボタンを押す → キャンセル**（該当行が自動削除され枠が開放されます）。
- 操作のたびに告知メッセージ本文が再描画され、**「参加 8/10名（残り2枠）」と参加者名が常に最新表示**されます。メッセージがそのまま出欠表として機能します。
- **満員時はキャンセル待ちに自動切り替え:** ボタンが「🈵 キャンセル待ちに登録」に変わり、押すと先着順で待ち行列に登録されます。空きが出ると**待ちの先頭が自動で参加に繰り上がり、本人へDMで通知**されます（早押し競争のない公平なFIFO方式）。
- キャンセル待ちが誰もいない状態で満員から空きが出たときのみ、告知メッセージの**スレッドに「空き枠が出ました（残りX枠）」が自動投稿**されます。
- **運営として参加（師匠・主催者・運営スタッフ向け）:** 「🛡 運営として参加」ボタンを押すと **状態「運営」** で登録され、**定員にカウントされません**（満員でも登録可・キャンセル待ちにも入りません）。出欠表には一般参加者とは別枠で「運営 N名（定員外）」と表示されます。すでに「参加」で登録済みの人がこのボタンを押すと運営へ切り替わり、空いた1枠へキャンセル待ちが繰り上がります。運営を辞めるときも「取り消す」でキャンセルできます。誰を運営とするかはリストで管理せず、本人がこのボタンで自己申告する方式です。
- イベント終了時刻を過ぎたイベントへのボタン操作は、一切処理されません（ガードレール）。
- 告知直後などに操作が集中した場合、「ただいま操作が混み合っています」と案内されることがあります。**数秒おいてもう一度押せば正しく処理**されます（同時押下で定員を超えることはありません）。

### 参加者のリアルタイム確認

- 告知メッセージ・カレンダー説明欄内のURL（`…/exec?eventId=EV_XXX`）を開くと、現在の参加者一覧（表示名）と残枠がブラウザで確認できます。

### イベントの変更・中止（主催者）

1. DMで受け取った **回答編集用URL** を開き、内容を修正して再送信します。
2. **ステータス「開催」のまま変更した場合:** スプレッドシート・カレンダー・Slack告知が最新情報に一括更新されます。
   - 日時・開催形式を変更した場合はカレンダー予定を作り直します（分割数の変化に追随）。**「Google Meet」の場合はMeet URLが再発行される**ため、参加者には告知メッセージの最新URLを案内してください（主催者へはDMで注意喚起されます）。
   - **開催日時・Discordの部屋・開催形式・場所のどれかを変更した場合は、告知スレッドに「変更前 → 変更後」を投稿し、参加登録中・キャンセル待ちの全員（運営を含む）をメンションします。**個別のDMは送りません（人数が多くても、投稿は1回で済み、中止・再開の通知と、同じ方式にそろえています）。複数を同時に変えたときは、1回の通知にまとめます。
   - 説明・準備・定員だけの変更は、通知しません（告知の表示だけ更新されます）。
   - 定員を現在の参加者数より減らした場合、既存の参加者はそのまま維持され、参加者数が新定員を下回るまで**新規の申込はキャンセル待ち扱い**になります。
   - 定員を増やした場合、**空いた枠の分だけキャンセル待ちが先着順で自動繰り上げ**され、本人へDMで通知されます。
3. **ステータスを「中止」に変更した場合:** カレンダーから予定が削除され、Slack告知が**【中止】表示に再描画（ボタンは消えます）**され、告知スレッドに中止のお知らせが投稿されます。**お知らせには、参加登録中・キャンセル待ちの全員（運営として参加した人を含む）のメンションが付く**ので、ボタンを押しただけでスレッドを見ていない人にも通知が届きます（個別のDMは送りません）。以降のボタン操作は処理されません。
   - すでに中止のイベントを再送信しても、中止のお知らせは繰り返し投稿されません（シートと告知の表示だけ更新されます）。
   - メンションの通知は、各人のSlackの通知設定（チャンネルのミュートなど）に左右されます。
4. **中止したイベントを、開催に戻す場合:** 同じ編集用URLから、ステータスを「開催」に戻して送信します。
   - **日時・開催形式が同じでも、カレンダー予定は必ず作り直されます**（中止のときに削除しているため）。Meet の場合は、URL が新しく発行されます。
   - 告知メッセージは【中止】が消えて、参加ボタンが戻ります。**参加登録は、そのまま残ります。**
   - Discord VC の場合は、部屋を取り直します。中止の間に他のイベントに取られていると、差し戻されます（理由と空いている部屋が、DMで届きます）。
   - **終了した日時のままでは、開催に戻せません**（戻しても、参加ボタンが使えないため）。日時を、これからのものに直してください。
   - 主催者へは「中止から開催に戻しました」とDMが届きます。
   - **告知スレッドに「中止から開催に戻りました」と、いまの日時・会場を投稿し、参加登録中・キャンセル待ちの全員（運営を含む）をメンションします。**（日時も一緒に変えた場合も、変更前後の通知ではなく、この1回にまとめます。）

## 師匠の追加・削除

誰が師匠かは、**管理用スプレッドシートの「師匠リスト」シート**で管理します（`bootstrap()` / `setupTriggers()` で自動作成）。GASエディタを開く必要はありません。

- **設定内容:** 1行に1人を書きます。

  | 列 | 内容 |
  |---|---|
  | SlackユーザーID | `U…` で始まるID。`<@U12345>` の形で貼り付けても構いません（自動で整形されます） |
  | 表示名 | 誰の行か分かるようにするためのメモ。処理には使いません |
  | 有効（未入力＝有効） | ドロップダウンで「有効」「無効」を選びます（**それ以外の入力は受け付けません**）。**未入力のままなら有効**です。行を消さずに外したいときに「無効」を使います |
  | メモ | 処理には使わない自由記入 |

- **反映のタイミング:** シートを編集した**その場で自動反映**されます。反映されると画面右下に「師匠リスト: 有効な師匠 N名を反映しました」とトーストが出るので、これを反映の確認に使ってください。
- **師匠を外すとき:** 行を削除するか、「有効」列で「無効」を選びます。どちらでも次に `/event` を打ったときから弟子用フォームのリンクが返るようになります。
- **打ち間違いの検知:** SlackユーザーIDの形式でない値は無視され、トーストに「ID形式ではないため無視: ○○」と表示されます。無反応で終わらないので、貼り付けミスにその場で気付けます。
- **SlackユーザーIDの調べ方:** Slackでその人のプロフィールを開き、「その他」（︙）→「メンバーIDをコピー」。
- **シート自体は削除・改名しないでください。** このシートが師匠の唯一の記録なので、消えれば師匠は0名になります。誤って消した場合は空のシートが自動で作り直され、**登録されていた師匠は全員外れます**（そうなったことはトーストとログで通知されます）。元に戻すには、シート名を戻すか、スプレッドシートの「ファイル > 版の履歴」から復元してください。復元後にどこか1セルを編集すれば、その時点の内容が反映されます。

> **補足:** このリストは「`/event` で師匠用フォームのリンクを返す相手」を決めるだけのものです。イベントが師匠イベントになるかどうかは**どちらのフォームから登録されたか**だけで決まるため、師匠が弟子用フォームから登録すれば弟子イベント扱いになります。

## 弟子の離脱アラート

師匠ごとに決めたチャンネルで、**指定した日数以上「投稿・スレッド返信・スタンプ」のどれもない人**を、毎朝その師匠へDMで知らせます。該当者がいない日は何も届きません。

### はじめ方

1. GASエディタで **`InactivityAlert.gs` を開き、`setupInactivityAlert()` を1度だけ手動実行**します。「離脱アラート設定」シートと、毎日動くトリガーが作られます。**`setupTriggers()` を実行する必要はありません**（ナイスチャレンジのフォーム説明文を手で直している場合、`setupTriggers()` はそれを上書きします）。
2. 「離脱アラート設定」シートに、師匠ごとに1行入れます。シートの右側（J列）にも設定のしかたが書いてあります。
3. 設定を入れたら、同じ `InactivityAlert.gs` で **`checkInactiveDisciplesNow()` を手動実行**すると、通知頻度に関係なく今すぐ判定して師匠へDMが届きます（「毎週月曜」の行も月曜を待たずに試せます）。
   手動実行のときだけ、該当者がいない行にも「該当者はいません」とDMが届きます（動いているかを確かめるため）。毎朝の自動実行では、該当者がいなければ何も届きません。
4. 対象チャンネルにBotを追加します（`/invite @Bot名`）。入っていないと読めず、師匠へその旨のDMが届きます。

### 設定シートの列

| 列 | 内容 |
|---|---|
| 師匠のSlackユーザーID | 通知を受け取る人。**必須** |
| 表示名 | 誰の行か分かるためのメモ。処理には使いません |
| 対象チャンネル | チェックするチャンネル。`#`なしの名前かチャンネルID。**公開チャンネルのみ。必須** |
| 日数 | この日数以上、活動がない人を知らせます。1以上の整数。**必須** |
| 通知頻度 | 「毎日」か「毎週月曜」。空欄は毎日。**日数が7日以上なら「毎週月曜」、7日未満なら「毎日」が目安**です（「毎週月曜」は月曜の時点だけを見るので、週の途中の空白は拾えず、通知も最大6日遅れます） |
| 除外する人 | 通知に出したくない人（完全に離脱した人など）。**通知に出た名前をそのまま書けます**。SlackユーザーIDでも書けます。カンマか改行で複数。師匠本人とBotは自動で外れます |
| 有効（未入力＝有効） | 「無効」にすると、その行の通知を止めます |
| メモ | 処理には使いません |

1行は「師匠1人 × チャンネル1つ」です。同じ師匠が複数のチャンネルを見たいときは、行を足します。

### 数え方で知っておくこと

- 通知には、メンションではなく**表示名の文字だけ**を並べます。
- 「除外する人」に書いた表示名が、同じ名前の人が複数いる、または見つからないときは、除外されません（実行ログに警告が出ます）。そのときはSlackユーザーIDで書いてください。
- 対象は、そのチャンネルに参加している人です（師匠本人・Bot・退会した人は除きます）。
- スタンプは、**日数以内に投稿されたメッセージに押したもの**だけ数えます。Slackが「いつ押したか」を返さないためです。古い投稿に押したスタンプは見えないので、通知が少し多めに出ることはあっても、見逃しはありません。同じ理由で、日数より古いスレッドへの返信も見えません。
- 通知は毎朝9時台に判定します。

## スタンプで別チャンネルへシェア（絵文字リアクション転送）

特定のスタンプ（絵文字リアクション）を押すだけで、そのメッセージを別チャンネルへ自動転送できます。「これはアーカイブに残したい」「このやり取りを別チャンネルにも流したい」というときに使えます。

- **設定場所:** 管理用スプレッドシートの「**絵文字転送マッピング**」シート（`bootstrap()` / `setupTriggers()` で自動作成）。
- **設定内容:** 1行に1ルールを書きます。

  | 列 | 内容 |
  |---|---|
  | 絵文字名 | `pin` でも `:pin:` でも可 |
  | 転送先チャンネル | `#archive` / `archive` / チャンネルID（`C…`）のいずれか |
  | 有効（未入力＝有効） | ドロップダウンで「有効」「無効」を選びます（師匠リストと同じ。それ以外の入力は受け付けません）。**未入力のままなら有効**です |
  | メモ | 処理には使わない自由記入 |

  同じ絵文字の行を複数書けば、その全チャンネルへ転送されます。
- **使い方:** マッピングにある絵文字を任意のメッセージに付ける → 転送先へそのメッセージのリンク（permalink）が投稿されます。本文は Slack が自動展開するので、元メッセージを編集すると転送先の見え方も追従します。
- **取り消し:** その絵文字リアクションを外すと、転送先の投稿も自動で削除されます。
- **補足:** 転送先チャンネルに Bot が入っていなくても投稿できます（`chat:write.public`）。転送の履歴は管理用スプレッドシートの「絵文字転送ログ」シートに監査記録として残ります（行は消さない運用。手で消すと同じメッセージが再転送されることがあります）。

## 一問一答クイズ

管理用スプレッドシートの「**クイズ問題**」シートに貼った問題を、上の行から順に1日1問ずつSlackへ出題します。出題メッセージに付いたスタンプは「**クイズ回答ログ**」に記録されます。3枚とも `bootstrap()` / `setupTriggers()` で自動作成されます。

### はじめ方

1. 「クイズ問題」シートに問題を貼ります（出題順に並べておきます。シャッフルしたいときは貼る前に済ませてください）。
2. 「クイズ設定」シートの「投稿先チャンネル」に `#チャンネル名` かチャンネルIDを入れます。
3. 投稿先チャンネルにBotを招待します（チャンネルで `/invite @Botの名前`）。

これだけで、次の投稿時刻から出題が始まります。GASエディタでの作業はありません。**投稿先チャンネルが空欄のあいだは何も起きない**ので、クイズを使わない期は放っておいて構いません。

> **Botの招待を忘れると、スタンプが記録されません。** 出題はBotがチャンネルにいなくてもできてしまうので、気づきにくいところです。Slackはスタンプが付いたという知らせを、Botが参加しているチャンネルの分しか送ってこないため、招待していないと「出題はされるのにクイズ回答ログが増えない」状態になります。招待する前に付けたスタンプは、あとから記録されません（付け直せば記録されます）。

### クイズ問題シートの列

| 列 | 書く人 | 内容 |
|---|---|---|
| 問題番号 | 運営 | 例: `Ord1-Q13`。見出しに入り、クイズ回答ログでは「Ord番号」「Q番号」に分けて記録されます |
| 問題文 | 運営 | 必須 |
| 画像（DriveのURLかID・任意） | 運営 | 画像付きで出したいときだけ。Googleドライブの共有リンクをそのまま貼れます。GASを実行している人が開ける画像にしてください |
| 出題日時 | Bot | 出題した日時 |
| 状態 | Bot | 「出題済み」か、飛ばした理由（例: 「⚠ 問題文が空のため飛ばしました」） |
| 出題メッセージID | Bot | スタンプの記録に使う内部の値（Slackがメッセージごとに付ける固有の番号）。クイズ回答ログの「出題メッセージID」と繋ぐキー。触らないでください |

- **「状態」に何か入っている行は出題されません。** 問題文が空・画像が読めないなど出せない行は、理由を書いて次の行を出します（出題は止まりません）。直した行をもう一度出したいときは、その行の「状態」を消してください。
- 全問出し終えると、それ以降は何も投稿しません。

### 出題を止める・再開する・日付を決めて始める

「クイズ設定」シートで操作します。どれも、反映は**毎時の判定のとき**です（設定を変えてから最大1時間ほどかかります）。

| やりたいこと | 操作 |
|---|---|
| 出題を始める | 「投稿先チャンネル」を入れて、「出題の切り替え」を「出題する」にする |
| 今すぐ止める | 「出題の切り替え」を「お休み」にする |
| 再開する | 「出題の切り替え」を「出題する」に戻す。前回の続きの問題から出ます（お休みしていた日の分は、まとめて出しません） |
| 明日から再開する（今日はもう出したくない） | 「出題の切り替え」を「出題する」に戻して、「出題を始める日」に明日の日付を選ぶ |
| お休みして、◯日から自動で再開する | 「出題を始める日」にその日付を選ぶ（「出題の切り替え」は「出題する」のまま） |

- 「出題を始める日」より前は出題しません。投稿時刻から出ます。過去の日付は無視されるので、あとで消す必要はありません。
- 「出題の切り替え」が「出題する」以外（空欄・書き間違い）のときは、お休みとして扱います。「出題を始める日」が日付として読めないときも、出題を止めます（実行ログに警告が出ます）。
- **「次の出題」**には、次にいつ・どの問題が出るかが自動で表示されます（入力は要りません）。例: `明日 10/13(火) 9時ごろ(Ord2-Q6)`。設定や問題を編集したときと、毎時の判定のときに更新されます。問題文が空・画像が読めない行は出題時に飛ばされるため、表示の問題番号が1つずれることがあります。
- 1問だけ飛ばしたいときは、その行の「クイズ問題」シートの「状態」に何か書いてください（出題対象から外れます）。

### クイズ設定シート

| 項目 | 既定値 | 内容 |
|---|---|---|
| 投稿先チャンネル | （空） | 空欄のあいだはクイズは動きません。Botをこのチャンネルに招待しておいてください |
| 出題の切り替え | 出題する | 「お休み」にすると出題しません。「出題する」に戻すと前回の続きから出します |
| 出題を始める日 | （空） | 空欄なら、すぐに出します。日付を選ぶと、その日より前は出しません |
| 次の出題 | （自動表示） | 次の出題の日時と問題番号。入力は要りません |
| 投稿時刻 | 9 | 0〜23（時）。その時台に出題します |
| 土日は休む | はい | 「いいえ」にすると土日も出題します |
| 見出し | `*今日の一問一答（{number}）*` | `{number}` が問題番号に置き換わります。空欄なら問題文だけ |
| 記録する絵文字 | タブった, tabutta | カンマ区切り。出題メッセージに付いたこの絵文字だけを記録します |
| Botの表示名 | （空） | 空欄ならいつものBot名 |
| Botのアイコン | （空） | `:絵文字名:` か画像のURL。空欄ならいつものアイコン |

- 値を変えたら、次の出題からそのまま効きます（GASエディタでの再実行は要りません）。
- 投稿時刻は「その時刻を過ぎていて、今日まだ出していなければ出す」という判定です。そのため、投稿時刻より後にクイズを始めると、その日のうちに1問出ます。Slackへの投稿に失敗した日は、次の時間に自動でやり直します。

### クイズ回答ログ

出題メッセージに「記録する絵文字」が付くと1行追加され、外すと「削除日時」が入ります（行は消えません。付け直すと新しい行になります）。Botが書くシートなので、手で編集すると警告が出ます。

## ナイスチャレンジ

「Vizをレビューしてほしい」人がGoogleフォームに回答すると、設定したチャンネルへ投稿されます。**親の投稿は見出しと案内だけ**で、**回答の内容と師匠へのメンションは、そのスレッドの最初の返信（Botの投稿）**に載ります。投稿に必ず返信が付くので、スレッドが最初から立ち、レビューの書き込み先が分かります。投稿に付いたスタンプとスレッド返信は、**投稿した本人の分を除いて**「**ナイスチャレンジレビューログ**」に記録されます（本文の返信に付いたスタンプも、親の投稿へのスタンプとして数えます。Botの返信は数えません。レビューがどれくらい集まったかを後から見るため）。3枚のシート（設定・投稿ログ・レビューログ）は `bootstrap()` / `setupTriggers()` で自動作成されます。

### はじめ方

1. 「ナイスチャレンジ設定」シートの「**フォームのIDまたはURL**」を確認します。`bootstrap()` で作った場合は、ナイスチャレンジ用フォームのURLがすでに入っています。**既存のフォームを使うときは、そのフォームの編集画面のURLに書き換えます**（書き換えた時点で、送信の受付が自動で追随します）。
2. 「ナイスチャレンジ設定」シートの「**投稿先チャンネル**」に `#チャンネル名` かチャンネルIDを入れます。
3. 投稿先チャンネルにBotを招待します。**招待しないと、スタンプと返信が記録されません。**
4. 投稿者には、Slackで **`/review`** を打ってもらいます。「投稿者のSlackユーザーID」が入力済みのフォームのリンクが、本人にだけ表示されます。既存のフォームを使う場合は、投稿者のSlackユーザーIDを入力する設問を用意し、「ナイスチャレンジ設定」の「投稿者のSlackユーザーIDの設問名」を設問名に合わせます（`setupTriggers()` を実行するか、設定シートを1度編集すると、コマンドが使うエントリIDが更新されます）。

フォームIDか投稿先チャンネルが空のあいだは何も起きません。

### 個人情報の扱いと、投稿の直し方

- メールアドレスは集めません。投稿者本人の特定には、フォームに入力された Slack ユーザーIDを使います。IDは投稿者のメンションと、本人のスタンプ・返信の除外にだけ使い、投稿には載せません。
- **スレッドの返信の本文は、「ナイスチャレンジレビューログ」の「返信内容」に保存します**（あとで分析するため）。返信が削除されたら本文も消え、編集されたら更新されます。投稿者本人の返信は記録しません。管理用スプレッドシートは、運営の編集者に見えることを前提にしてください。
- **フォームの回答は「回答を残す日数」（既定7日）だけ残し、過ぎたら毎日の自動処理（朝4時ごろ）が削除します。** 削除した日時は「ナイスチャレンジ投稿ログ」に入ります。
- 残している間は、**投稿者へ回答の編集用URLをDMで送ります。** 本人がそのURLから回答を直すと、スレッド内の本文と、親の投稿の概要・対象も同じ内容に更新されます（スタンプ・返信・集計はそのまま引き継がれます）。期間を過ぎたら直せなくなるので、直したいときは、もう一度フォームに回答してもらい、古い投稿は運営がSlackから削除してください。
- 次の場合は、**回答をすぐ削除**します。編集用URLを渡せないか、渡す必要がないためです。
  - 「回答を残す日数」が0のとき（編集はできません）
  - 入力されたIDが読み取れなかったとき（形式の誤りなど）。投稿は出ますが、投稿者が「本人不明」になり、その投稿では**本人のスタンプ・返信を除外できません**。運営が見て判断してください。
- **形式は正しいが、Slackに存在しないID**（打ち間違いなど）のときは、**投稿しません**。投稿者本人には知らせる手段がないので、「チャンネルに出ない」ことで気づいてもらいます。回答はフォームに残り、**自動では削除されません**。運営がフォームの「回答」タブで確認し、不要なら削除してください。
  - 気づいてもらうため、フォームの送信後メッセージに「投稿されない場合は、IDを確認してもう一度送信してください」と書いておきます。`bootstrap()` が作るフォームには最初から入ります。**すでにあるフォームには入らない**ので、フォームの「設定」→「プレゼンテーション」→「確認メッセージ」に貼ってください。
  - 確認できなかったとき（Slackとの通信の失敗など）は、存在するものとして通常どおり投稿します。
- **投稿に失敗した回答は削除しません。** 再処理のためで、運営が確認して対応してください（投稿者を特定できていれば、本人にDMで知らせます）。
- フォームが**回答シートに紐づいていると、フォームの回答を消してもシート側の行が残ります**。紐づけないでください。紐づいているときは実行ログに警告が出ます。フォームの「回答」タブで「リンク解除」し、シートの行も消してください。
- 編集用URLは本人以外に渡さないよう、DMに注意書きを添えています。

### 投稿の形

投稿の形は**固定**です（シートでは変えられません。変えたいときはコードの変更になります）。

**親の投稿**（チャンネルの流れに出る部分）:

```
@投稿者 さんがVizのレビューを募集しています :eyes:（詳細はスレッドにて :point_down:）
概要: …            ← 記入があるときだけ
対象: …            ← 記入があるときだけ
```

**スレッドの最初の返信**（Botが投稿する本文）:

```
*所属部屋*
…
*概要*
…
*成果物のリンク*
…
*FBを受けたい対象*
…
*成果物の状態*
…
*欲しいFB*
…
*相談内容*          ← 記入があるときだけ
…

@師匠A @師匠B … レビューをお願いします :pray:
```

- 見出しと並びはコードで決まっています。フォームの設問名は注記つきで長いので、投稿には短い見出しを使います。
- 回答が空の設問は、見出しごと載りません。
- **「概要」の設問**（「活動の概要をひとことで！（※必須）」）は、親の投稿に載せるための設問です。ナイスチャレンジは活動の共有が目的で、フィードバックを求めない投稿もあるため、任意の「相談内容」ではなく、必須の「概要」を使います。**`bootstrap()` が作るフォームには最初から入りますが、すでにあるフォームには入りません。** フォームの編集画面で、「成果物のリンク」の前に短い回答の設問を足してください。**設問のタイトルは「活動の概要をひとことで！（※必須）」と完全一致**させ、「必須」にします。足していないあいだは、親の投稿の「概要」の行が出ないだけで、投稿は動きます。
- 回答に `<!channel>` などが書かれていても、メンションとしては働きません。
- Botの表示名とアイコンは「ナイスチャレンジ設定」で変えられます。投稿者を特定できなかったときは、親の投稿の冒頭が「メンバー さんが…」になります。

### 師匠へのメンション

投稿には、**「師匠リスト」シートの有効な師匠全員**へのメンションが付きます（部屋による振り分けはありません）。師匠の追加・削除は「師匠リスト」を編集するだけで、`/event` の師匠用フォームの配布先と同じ一覧が使われます。

- 師匠が0人のときは、この行は出ません。
- 投稿者本人が師匠のときは、自分へのメンションは付きません。
- 回答を編集すると、そのときの師匠リストで投稿が書き換わります。**編集で新しく足したメンションは、通知が飛ばない場合があります**（Slackの仕様です）。

### ナイスチャレンジ設定シート

| 項目 | 既定値 | 内容 |
|---|---|---|
| フォームのIDまたはURL | （bootstrapで作成したフォーム） | 回答を受け取るフォーム。差し替えはここを書き換えるだけ |
| 投稿先チャンネル | （空） | 空欄のあいだは動きません |
| 投稿者のSlackユーザーIDの設問名 | 投稿者のSlackユーザーID | フォームの設問名と完全一致 |
| 所属部屋の表記 | `{師匠名}部屋` | フォームの「所属部屋」の選択肢の書き方。`{師匠名}` が師匠リストの表示名になる |
| ナイスチャレンジのチャンネルのリンク | （空） | フォームの説明文の `{ナイスチャレンジ}` に入るSlackチャンネルのリンク。チャンネルを右クリック →「リンクをコピー」で取れる |
| よくある質問のチャンネルのリンク | （空） | 同じく `{よくある質問}` に入るリンク |
| フォームの説明文（冒頭） | （既定の文） | フォームの先頭に出る説明。書き換えるとフォームの説明がその場で変わる。空欄ならフォーム側に触らない |
| フォームの説明文（2ページ目） | （既定の文） | 「フィードバックを受けたい内容の記載」セクションの説明。置き換えの印は冒頭と同じ |
| 回答を残す日数（編集できる期間） | 7 | 0〜365（日）。この間は回答の編集が投稿に反映される。過ぎたら自動で削除。0ならすぐ削除（編集不可） |
| Botの表示名 / アイコン | （空） | 空欄ならいつもの表示 |

### 所属部屋の選択肢

フォームの「所属部屋」（プルダウン）の選択肢は、**「師匠リスト」シートの有効な行の「表示名」**から自動で作られます。1人が1つで、「ナイスチャレンジ設定」の「所属部屋の表記」（既定は `{師匠名}部屋`）の `{師匠名}` に表示名が入ります（例: 表示名が「田中」なら「田中部屋」）。

- 師匠リストを編集すると、フォームの選択肢がその場で貼り直されます（画面右下にトーストが出ます）。並びは師匠リストの並びのままです。
- **表示名が空の行は選択肢に出ません。** 「無効」にした師匠も出ません。
- 有効で表示名のある師匠が0人のときは、フォームの選択肢を変えません。
- 設問名が「所属部屋」のプルダウンがあれば、既存のフォームでも同じように反映されます。
- 所属部屋は投稿に載るだけで、メンション先は変わりません（師匠リストの有効な師匠全員にメンションされます）。

### ログシート

- **ナイスチャレンジ投稿ログ**（Botが書く）: 1投稿1行。投稿日時・投稿者・**スタンプ数・返信数・返信した人数**・投稿内容（スレッド内の本文）・フォーム回答の削除日時・**本文の返信ID**など（削除日時が空なら、回答はまだフォームに残っています）。本文の返信IDが空の行は、本文を親の投稿に載せていた頃の投稿です。3つの数は数式で、レビューログから「本人以外で、取り消されていないもの」を数えます。行を並べ替えても崩れません。
- **ナイスチャレンジレビューログ**（Botが書く）: 1スタンプ・1返信で1行。種類・ユーザーID・絵文字・**投稿ID**・削除日時・**返信ID**・**投稿者・投稿内容・返信内容**。スタンプを外す／返信を削除すると「削除日時」が入ります（行は消えません）。
  - **投稿者・投稿内容**は、投稿ログから引く数式です（対象の投稿が何だったかを、人が読めるようにするため）。これまでの行にも、`setupTriggers()` で入ります。
  - **返信内容**は、返信の本文です（あとで分析するため）。**返信が削除されたら本文も消え**、編集されたら更新されます。投稿者本人の返信は記録しません。
  - 返信の本文は、人が書いた文章です。管理用スプレッドシートの共有範囲（運営の編集者）に見えることを前提にしてください。

- **「投稿ID」は、2枚のログを繋ぐキーです。** 親の投稿の、Slackがメッセージごとに付ける固有の番号（`1791296225.285359` のような、投稿の時刻を元にした値）で、投稿ログの「投稿ID」とレビューログの「投稿ID」が同じ投稿を指します。1つの投稿に、スタンプや返信が複数付くので、「投稿ログ 1行 ↔ レビューログ 複数行」の関係です。表計算ソフトなどで読み込むときは、**文字列として**読んでください（数値に変換されると桁が落ちて、繋がらなくなります）。人が読む値ではないので、手で編集しないでください。

どちらも手で編集すると警告が出ます。スタンプ数は「誰が何のスタンプを何個」で数えるので、1人が3種類のスタンプを付けると3になります。

> **Slack側の設定:** `/review` コマンド（`commands` スコープ）と、返信を受け取る `message.channels` イベントが必要です（[`slack/manifest.yml`](../slack/manifest.yml)）。既存のインスタンスでは、マニフェストを反映してアプリを**再インストール**してください。公開チャンネルのみ対象です。

## トラブルシューティング / FAQ

**Q. フォームを送信したのにSlackに告知が投稿されない**
次の順で確認してください。
1. 主催者へDMが届いていないか（入力ミスで差し戻されている場合、理由と修正リンクがDMで届きます）。
2. `setupTriggers()` を実行済みか（フォーム送信トリガーが未登録だとGASが起動しません）。
3. Botが告知チャンネルに招待されているか（`/invite @アプリ名`）。
4. スクリプトプロパティの `SLACK_BOT_TOKEN`・`SLACK_CHANNEL_ID`・フォームIDに誤りがないか。
5. GASエディタの「実行数」でエラーログを確認（出るログの見方は、下の「実行ログの見方」）。

次のような案内が出ていれば、それが原因です。
- **告知チャンネルに「フォームからのイベント登録を受け付けられませんでした」と出ている**: 主催者のSlackユーザーIDが不正、またはSlackに存在しません（打ち間違い）。イベントは登録されていません。Slackで `/event` を打って届くフォームから、登録し直してください。
- **主催者へのDMに「Slackへ告知を投稿できなかったため、登録しませんでした」と届いている**: 告知チャンネルの設定（`SLACK_CHANNEL_ID`）とBotの招待を確認してください。登録は取り消されています（カレンダー予定も消えています）。確認したら、DMのURLから同じ内容を再送信できます。

**Q. ボタンを押したら「応答に失敗した」と警告が出た**
GASのコールドスタートで3秒ルールを超過したときに出ますが、**処理自体は完了しています**。告知メッセージの再描画で結果を確認してください（[SETUP.md](SETUP.md) 手順7 の注記参照）。

**Q. `/event` のリンクを開いても主催者IDが入力済みにならない**
`setupPrefillEntryIds()` が未実行か、フォームの設問を作り直してエントリIDが変わっています。`setupPrefillEntryIds()` を（再）実行してください。

**Q. 編集用URLなどのDMが届かない**
まず **サイドバーの「App」欄** を確認してください。BotからのDMは通常のDM欄ではなくApp欄（Botアプリ名の会話）に届くため、見落としやすいです（App欄に表示されていない場合は、Slack内検索でアプリ名を探すと会話が見つかります）。それでも届いていない場合は、GASエディタの「実行数」でログを確認してください。`Slack API error: conversations.open -> missing_scope` なら `im:write` スコープの追加漏れ（追加後のアプリ再インストール漏れ）、`user_not_found` なら主催者のSlackユーザーIDの誤りです。

**Q. 主催者が編集用URLのDMを紛失した**
公開用スプレッドシートのイベントマスターに編集用URL列があるので、そこから参照できます（師匠イベントは公開シートに載らないため、管理者が管理用シートから該当URLを渡してください）。

**Q. コードを修正したら動かなくなった**
「新しいデプロイ」を作るとWebアプリのURLが変わり、SlackのRequest URLと不一致になります。「デプロイを管理」から**既存デプロイの新バージョン**として更新してください。

**Q. 師匠・弟子の区別が不要なコミュニティでも使える?**
使えます。師匠用フォームと `MASTER_FORM_ID` を設定せず、「師匠リスト」シートを空のままにしておけば、全イベントが弟子イベント（通常イベント）として扱われる1フォーム構成になります。

**Q. 師匠リストに追加したのに、その人に師匠用フォームが届かない**
シートを編集したときに右下へ「師匠リスト: 有効な師匠 N名を反映しました」のトーストが出たか確認してください。

- **トーストにその人が数えられていない**（「ID形式ではないため無視」と出ている）: SlackユーザーIDの打ち間違いです。正しいIDを貼り直してください。
- **トーストが出ない**: 編集トリガーが外れています。GASエディタで `setupTriggers()` を再実行してください。
- **トーストは出たが届かない**: 「有効」列が「無効」になっていないか、`MASTER_FORM_ID`（師匠用フォーム）が未設定でないかを確認してください。師匠用フォームが未設定の場合は、師匠にも弟子用フォームのリンクが返ります。

**Q. 公開シートの参加者リストが最新でない**
仕様です。公開用への参加者リスト同期は5分毎のため、最大5分の遅延があります。リアルタイムの状況はSlack告知メッセージまたは参加者確認Webページで確認してください。

**Q. 「カレンダーを開く」を押して追加したのに、予定が表示されない**
複数のGoogleアカウントにログインしていて、普段使っていない方のアカウントに追加された可能性があります。Googleカレンダー右上のアカウント表示を確認し、違っていればアカウントを切り替えてリンクを押し直してください。間違えて追加した分は、左サイドバー「他のカレンダー」の該当カレンダーから「登録を解除」で消せます（メンバーの権限は閲覧のみのため、間違えた側でイベントを変更・削除してしまう心配はありません）。

**Q. カレンダーに追加せずに予定を見たい**
Slackの告知メッセージに日時・場所・Meet URLがすべて載っており、状態が変わるたびに再描画されるため、これが常に最新の「正」です。全イベントの一覧は公開用スプレッドシートでも確認できます。

**Q. ナイスチャレンジのフォームに回答したのに、チャンネルに投稿されない**
次の順で確認してください。
1. 「ナイスチャレンジ設定」の「フォームのIDまたはURL」と「投稿先チャンネル」が入っているか（空欄のあいだは何も起きません）。
2. **投稿者のSlackユーザーIDが、Slackに存在するか。** 打ち間違いなどで存在しないIDのときは、投稿されません。回答はフォームに残ります。本人に「IDを確認してもう一度送信」と伝えてください（`/review` で開けば、IDは自動で入ります）。
3. 投稿先チャンネルにBotが招待されているか。
4. GASエディタの「実行数」のログを確認（下の「実行ログの見方」）。

**Q. クイズが出題されない**
「クイズ設定」シートの **「次の出題」** を見てください。出題されない理由が、そのまま書かれています。

| 「次の出題」の表示 | 意味と対処 |
|---|---|
| 投稿先チャンネルが空のため、出題しません | 「投稿先チャンネル」を入れる |
| お休み中です | 「出題の切り替え」を「出題する」に戻す |
| 「出題を始める日」が日付として読めないため、出題しません | 「出題を始める日」をカレンダーから選び直す（または空欄にする） |
| 「投稿時刻」が0〜23の数字ではないため、出題しません | 「投稿時刻」を0〜23の数字にする |
| 未出題の問題がありません | 「クイズ問題」シートに問題を足す（「状態」が埋まった行は出題されません） |
| 日付と時刻（例: 明日 10/13(火) 9時ごろ） | 正常です。その時刻の判定（毎時）で出題されます |

表示が更新されない場合は、編集トリガーが外れています。GASエディタで `setupTriggers()` を再実行してください。

### 実行ログの見方

GASエディタの「実行数」で、関数ごとのログを確認できます。次のログは、原因の切り分けに使えます。

| ログ | 意味 |
|---|---|
| 主催者のSlackユーザーIDが見つかりません。登録しませんでした | 主催者IDがSlackに存在しない。イベントは登録されていない（告知チャンネルに案内が出ている） |
| Slackへの告知を投稿できませんでした。登録を取り消します | 告知の投稿に失敗した。カレンダー予定を消し、主催者へ再送信を案内した。Botの招待・チャンネル設定を確認 |
| 投稿者のSlackユーザーIDが見つかりません。投稿しませんでした | ナイスチャレンジの投稿者IDがSlackに存在しない。回答はフォームに残っている |
| クイズ設定の「出題を始める日」が日付として読めないため出題しません | 日付のセルが日付として読めない。カレンダーから選び直す |
| クイズ設定の「投稿時刻」が 0〜23 の数字ではないため出題しません | 投稿時刻を直す |
| 「クイズ設定」に項目を追加しました: … | `setupTriggers()` が、クイズ設定に足りない項目を足した（情報。対処は不要） |
| 「次の出題」の表示を更新できませんでした | 表示だけの失敗（出題には影響しない）。続くようなら `setupTriggers()` を再実行 |
| カレンダーの呼び出しを再試行します | カレンダーの回数制限（Rate Limit Exceeded）に当たり、少し待ってやり直した（情報。最大3回まで自動で再試行する） |
| カレンダー予定が存在しないため、作り直します | カレンダー側で予定が消されていたので、作り直した（手で消された・中止で削除済みなど） |
| カレンダーの説明欄を更新できませんでした | 説明欄だけの失敗。予定・記録・告知・通知は済んでいる（主催者のDMにも、その旨が出る） |
| フォーム送信の処理に失敗しました | 処理の途中でエラーが起きた。**主催者にもエラーのDMが届いている**。続けて出る詳細（`API call to … failed with error: …`）が原因 |
